## Purpose
This workflow describes how the company fulfills a customer order from submission through delivery, including payment, inventory, shipping, and failure handling.

## Metadata
- domain: 
- owner: Fulfillment Operations Team
- version: 0.1.1
- actors: Customer, Warehouse
- systems: Online Store, Payment Gateway, Warehouse Management System, Carrier API, Email Service
- triggers: Customer submits an order through the online store
- start states: Order received
- end states: Order delivered, Order cancelled, Order failed
- tags: 

## Inputs
- Order submission through online store

## Outputs
- Order confirmation to customer
- Inventory reservation status
- Shipment creation status
- Order delivery status
- Cancellation notification to customer
- Failure notification to customer

## Business Rules
- Orders must be shipped within 24 hours of payment confirmation
- Partial shipments are not allowed — an order ships only when every item is available [human]

## API Interfaces
- Payment Gateway (validate payment)
- Warehouse Management System (reserve inventory, pick and pack)
- Carrier API (create shipment)

## Systems Involved
- Online Store
- Payment Gateway
- Warehouse Management System
- Carrier API
- Email Service

## Timers and SLAs
- 24 hours for shipment after payment confirmation

## Retries
- Up to 5 retries for shipment creation failure [human]
- up to 3 times

## Activities
- [a1] Validate order and payment
- [a2] Reserve inventory — parallel: g1
- [a3] Send order confirmation — parallel: g1
- [a4] Notify warehouse to begin picking — parallel: g1
- [a5] Pick and pack items
- [a6] Create shipment via Carrier API
- [a7] Ship order
- [a8] Release reserved inventory
- [a9] Obtain manager approval for orders above $1,000
- [a10] Notify finance team for orders above $1,000 [human]

## Decisions
- [d1] Is payment valid? — after: a1; yes: a2; no: e1
- [d2] Did shipment creation fail after retries? — after: a6; yes: a8; no: a7
- [d3] Is order value above $1,000? — after: a1; yes: a9; no: a2

## Exceptions
- [e1] Payment Declined — raised by: a1
- [e2] Shipment Creation Failed — raised by: a6
- [e3] SLA-breach alert — raised by: a6

## Compensations
- [c1] Release Inventory — compensates: a2

## Events
- [ev1] Order Submitted — kind: trigger; emitted by: start
- [ev2] Order Confirmed — kind: output_emit; emitted by: a3
- [ev3] Shipment Created — kind: output_emit; emitted by: a6
- [ev4] Order Delivered — kind: output_emit; emitted by: a7
- [ev5] Order Cancelled — kind: output_emit; emitted by: e1
- [ev6] Order Failed — kind: output_emit; emitted by: e2

## State Transitions
- Order received -> Payment Validation (trigger: Order submitted)
- Payment Validation -> Inventory Reservation (trigger: Payment valid)
- Payment Validation -> Order Cancelled (trigger: Payment declined)
- Inventory Reservation -> Picking and Packing (trigger: Inventory reserved)
- Picking and Packing -> Shipment Creation (trigger: Items packed)
- Shipment Creation -> Order Shipped (trigger: Shipment created)
- Shipment Creation -> Order Failed (trigger: Shipment creation failed)
